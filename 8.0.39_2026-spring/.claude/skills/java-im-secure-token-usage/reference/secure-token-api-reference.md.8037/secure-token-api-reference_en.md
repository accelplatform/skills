# SecureToken API Reference (Java)

Based on the actual class definitions in the `im_core_base` module (`jp.co.intra_mart.foundation.secure_token.*`). Do not supplement methods/attributes from memory or guesswork.

## Package Structure

```
jp.co.intra_mart.foundation.secure_token
├── SecureTokenManager   … Public API. Entry point for token issuance and verification
├── SecureToken          … Model class representing an issued token
└── SecureTokenException … Exception thrown during token processing (checked)
```

## The `SecureTokenManager` Class

```java
package jp.co.intra_mart.foundation.secure_token;

public class SecureTokenManager {

    /** The name used to set the token in the request parameter ("im_secure_token"). */
    public static final String REQUEST_PARAMETER_NAME = "im_secure_token";

    /** The session attribute name under which the token is stored. */
    public static final String SESSION_ATTRIBUTE_NAME = "...";

    /**
     * Constructor.
     * @param request the request
     */
    public SecureTokenManager(ServletRequest request);

    /**
     * Generates a token. The generated token is stored in the session.
     * The token generated by this method does not include parameter information.
     * @param useOneTimeToken true: a one-time-only token; false: a reusable token
     * @return the token
     * @throws SecureTokenException if an exception occurs while generating the token
     */
    public SecureToken createToken(boolean useOneTimeToken) throws SecureTokenException;

    /**
     * Generates a token. Specifying parameters produces a token that hashes those parameters.
     * By hashing the received parameters the same way on the receiving screen, you can check
     * whether the parameters were altered.
     * @param useOneTimeToken true: a one-time-only token; false: a reusable token
     * @param parameter the parameters (specify as a List even for a single value)
     * @return the token
     * @throws SecureTokenException if an exception occurs while generating the token
     */
    public SecureToken createToken(boolean useOneTimeToken, Map<String, List<String>> parameter) throws SecureTokenException;

    /**
     * Checks the validity of the token. Retrieves the token from the request parameter ("im_secure_token").
     * @return true if the token is valid
     * @throws SecureTokenException if an exception occurs while verifying the token
     */
    public boolean verify() throws SecureTokenException;

    /**
     * Checks the validity of the specified token.
     * @param token the token to verify
     * @return true if the token is valid
     * @throws SecureTokenException if an exception occurs while verifying the token
     * @since 8.0.11
     */
    public boolean verify(String token) throws SecureTokenException;

    /**
     * Checks the validity of the specified token and parameters.
     * @param token the token to verify
     * @param parameter the parameters used when generating the token (for comparison)
     * @return true if the token is valid
     * @throws SecureTokenException if an exception occurs while verifying the token
     * @since 8.0.11
     */
    public boolean verify(String token, Map<String, List<String>> parameter) throws SecureTokenException;
}
```

### Conditions Under Which `verify()` Returns `false`

- The token is not included in the request parameters
- The token is not valid
- The parameter values differ from those used when the token was generated
- The token has already been invalidated

### A Development-Only Setting to Skip Verification

Setting the system property `jp.co.intra_mart.foundation.secure_token.SecureTokenManager.ignore_token_check` to `true` makes the `verify()` methods always return `true`. **This is a development-only setting; do not use it in a production environment** (as noted explicitly in the Javadoc).

## The `SecureToken` Class (Model for an Issued Token)

```java
package jp.co.intra_mart.foundation.secure_token;

public class SecureToken implements Serializable {

    public SecureToken(String secureToken, boolean useOneTime, Set<String> parameterNameSet);

    /**
     * Invalidates this token (actually invalidated only in the case of a one-time token).
     */
    public void disable();

    /**
     * Retrieves the set of parameter names used when the token was generated.
     * @throws SecureTokenException if already invalidated
     */
    public Set<String> getParameterNameSet() throws SecureTokenException;

    /**
     * Retrieves the token string.
     * @throws SecureTokenException if already invalidated
     */
    public String getString() throws SecureTokenException;

    /**
     * Returns whether this is a one-time token.
     * @throws SecureTokenException if already invalidated
     */
    public boolean isOneTime() throws SecureTokenException;
}
```

- `disable()`/`getString()`, etc. each carry a guard based on the invalidation state, which **prevents an already-used one-time token from being retrieved again**. Calling `getString()`, etc. after invalidation throws a `SecureTokenException`
- When `useOneTime = false` (a reusable token), calling `disable()` does not actually invalidate it (internally, the `enable` flag is only dropped when `useOneTime` is true)

## The `SecureTokenException` Class

```java
package jp.co.intra_mart.foundation.secure_token;

public class SecureTokenException extends Exception {

    public SecureTokenException();
    public SecureTokenException(String message);
    public SecureTokenException(String message, Throwable cause);
    public SecureTokenException(Throwable cause);
}
```

A checked exception extending `java.lang.Exception`. All of the `createToken`/`verify` methods declare `throws SecureTokenException`.

## How to Obtain an `HttpServletRequest`

The `SecureTokenManager` constructor requires a `ServletRequest`. In contexts where it's passed directly as an argument (such as a Servlet's `doGet`/`doPost`), use it as-is.

**In contexts where the request isn't passed as an argument** (a custom tag, a utility class, etc.), you can obtain the `HttpServletRequest` bound to the current thread via `HTTPContextManager`.

```java
package jp.co.intra_mart.common.aid.jsdk.javax.servlet.http;

public abstract class HTTPContextManager {

    /**
     * Obtains the HTTP context manager instance.
     */
    public static HTTPContextManager getInstance();

    /**
     * Returns the HTTP context bound to the current thread.
     */
    public HTTPContext getCurrentContext();
}

public interface HTTPContext {
    ServletContext getServletContext();
    HttpServletRequest getRequest();
    HttpServletResponse getResponse();
    HttpSession getSession();
    HttpSession getCurrentSession();
}
```

Usage example (from the actual platform class `jp.co.intra_mart.system.comet.jssp.tag.ReverseAjaxTag`):

```java
final HttpServletRequest request = HTTPContextManager.getInstance().getCurrentContext().getRequest();
final SecureTokenManager tokenManager = new SecureTokenManager(request);
final SecureToken token = tokenManager.createToken(false);
```

Since `getCurrentContext()` returns the context "bound to the current thread," any Java class invoked from within an HTTP request-processing thread — a Servlet, a custom tag, or any class called further downstream — can obtain the same `HttpServletRequest` this way.
