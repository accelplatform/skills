# spec.json 结构（build-test-spec.js / build-test-spec-html.js 共用的输入）

`scripts/build-test-spec.js`（xlsx 输出）与 `scripts/build-test-spec-html.js`（HTML 输出）可直接使用同一份 spec.json。全部使用原生 JSON 值描述（非 TypeScript）。
实例见 [examples/equip-001.spec.json](../examples/equip-001.spec.json)。

```jsonc
{

  // 推导 docs/test-specs/xlsx|html/ 下的默认文件名（<key>-test.xxx）。
  "key": "equip-001",

  // 输出目标 xlsx 路径（相对于项目根目录，也可用 --out 覆盖）。
  // 省略时默认为 docs/test-specs/xlsx/<key>-test.xlsx
  "outputFile": "docs/test-specs/xlsx/equip-001-test.xlsx",

  // 输出目标 HTML 路径（省略时默认为 docs/test-specs/html/<key>-test.html）
  "outputFileHtml": "docs/test-specs/html/equip-001-test.html",

  "style": {
    "headerFill": "#D6DCE5",      // 表头背景色。若从包含主题色+tint的原模板中提取，

    "headerFontColor": "#000000",
    "fontName": "Yu Gothic",
    "fontSize": "9pt"
  },

  // ---- 前提条件工作表 ----
  // 二维数组，每个数组对应一行。空单元格可写 "" 或省略（数组可以缩短）。
```

## 前提条件工作表内容指南（原则）

参照原模板（intra-mart JSSP 项目的实际测试项目书）的结构，建议包含以下章节。若规格书中没有相关信息，应明确标注（"TBD""不适用"等）。

1. 测试概要（测试观点）— 说明本测试要确认什么的要点列表。若有非功能需求（响应时间等），应在此处明确
2. 测试环境信息 — 版本、数据库、应用服务器等
3. 测试实施环境信息 — 操作系统・浏览器
4. 所需应用程序
5. 所需模块
6. 所需文件 — 主数据、测试用户等
7. 测试前所需的设置・准备工作 — 主数据录入步骤、测试数据准备
8. 注意事项 — 时区、工作日定义等，若规格书有"通用定义"章节应转载
9. 本测试项目书之外的既有需求
10. 补充资料 — 所引用的 spec/*.md 路径列表

## 测试观点一览表的制作方法（原则）

将规格书的验收标准表（通常在 business-requirements.md 等文件中、含有类似 `AC-F001-01` 这样ID的表格）机械式地转换为每行一条记录。

- **功能ID**：对应 system-requirements.md 中的功能需求编号（如 `F-001-1`）
- **对象画面ID/画面名**：与规格书的"画面一览"表核对，判断该验收标准对应哪个画面的操作。无画面的批处理・通知处理应明确标注为 `(批处理)` 等
- **测试观点分类**：若验收标准表中有"模式"列（事件驱动/状态驱动/约束/复合/普遍性/可选等），直接沿用；否则可按"正常场景/异常场景/约束/复合"等分类
- **优先级**：根据业务关键程度判断。核心业务流程（如申请〜审批〜借用〜归还）或涉及金额约束的项目应定为"高"，周边功能（报表・通知细节等）可定为"低"

## 按画面制作测试项目书的方法（原则）

将目标画面的验收标准分解到实际画面操作的粒度。一条验收标准通常会产生多个测试项目（正常模式、边界值、异常场景应分别成行）。

- 显示区域应根据规格书推测画面的UI结构（检索条件区域／列表区域／表单／按钮等）。若详细设计中有画面线框图，应优先参考
- 原则上一个项目对应一个测试观点和一个预期结果（expected）。避免"既……又……"这类复合预期结果，必要时应拆分为多行
- **操作（`action`）不要写成"检索・选择""点击"这类抽象标签，而应写成测试人员可直接照做的具体操作步骤**。需明确写出输入值示例（机型名・天数・金额等）以及具体操作的UI元素（按钮名称・单选框・复选框・下拉菜单等）
- **以一行一个操作为原则，用 `\n` 分隔并加上"1. ""2. "……编号，拆分为多行**。xlsx 与 HTML 均会将包含 `\n` 的字符串原样渲染为单元格内换行（xlsx 已设置 `alignment.wrapText: true`，HTML 已设置 `white-space: pre-wrap`，无需额外配置）。不要将点击・输入・确认等多个操作揉进一行
  - 好的示例：`"1. 在检索栏输入「笔记本电脑」\n2. 点击检索按钮\n3. 从检索结果列表中选择目标行"`
  - 不好的示例：`"检索・选择"`（不清楚检索什么、如何选择）／`"在栏内输入后点击"`（一行塞入了过多操作）
- 备注（note）中务必记录原始验收标准ID（如 `AC-F001-05`），以保持可追溯性（从测试项目反查验收标准）
