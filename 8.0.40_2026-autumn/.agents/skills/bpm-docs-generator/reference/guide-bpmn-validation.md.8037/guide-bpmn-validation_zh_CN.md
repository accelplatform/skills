# BPMN 语法・引用完整性验证指南

定义在读取 BPMN 文件后立即实施的「BPMN 语法・引用完整性验证」的具体步骤与记载规则。

## 目的
尽早检测 BPMN 2.0 XML 的记法缺陷・引用断裂・与图形信息的对应偏差，并判断是否可进入规格书创建（step.3）。

## 执行步骤（必须）

**使用脚本：** `.agents/skills/bpm-docs-generator/scripts/validate-bpmn.js`

```sh
# 基本
{{RUNTIME}} .agents/skills/bpm-docs-generator/scripts/validate-bpmn.js <diagram.bpmn>
# 指定追加规则时
{{RUNTIME}} .agents/skills/bpm-docs-generator/scripts/validate-bpmn.js <diagram.bpmn> --rules <rules.json>
```

**退出码：** 0 = 成功（仅有 warning 或无）／ 1 = 失败（存在 error）

**执行顺序（读取 BPMN 文件后必须立即实施）：**
1. 执行 validate-bpmn.js。
   - 验证观点：命名空间一致性（`xmlns:bpmn`、`xmlns:bpmndi`）・连接来源/连接目标的一致性・与图形布局的对应一致性・startEvent/endEvent 的存在
2. 对验证结果进行详细分析。
   - **实施错误分类**
     - 不要仅凭查看各个错误就判定其为「实际问题」还是「工具误检测」。
     - 应确认以下信息后进行判定：
       - BPMN XML 中相应要素的实现状况（输出示例：`<bpmn:startEvent id="...">` 是否存在）
   - **实施重要度判定**
     - 仅作「错误」「警告」的分类是不充分的。
     - 需确认是否实际影响 IM-BPM 导入或流程执行。
     - 即使无影响，也应从运用・可维护性的观点重新评估重要度。
   - **深入挖掘原因候选**
     - 确认工具的输出规格（iGrafx 时为版本、导出设置）
     - 与类似流程的比较（相同错误是否存在于其他流程中）
   - **实施影响分析**
     - 重视「是否影响规格书的创建」。
     - 同时讨论在实现或测试阶段产生影响的可能性。
     - 即使判断为「可忽略」，也应明确记载理由。
3. 将验证结果反映到 to-be-discussed.md。
4. 判断是否可进入 step.3。

**注意事项**
- validate-bpmn.js 中未实现的观点，不得记载于 BPMN 语法・引用完整性验证结果中。
- 不实施 validate-bpmn.js 中不存在的新的语法检查、引用检查、标准合规检查等。
- 此外，不对 validate-bpmn.js 中不存在的检查实施本指南的详细分析。
- 不应只是照搬错误日志，而应写成使用者能够明白下一步该采取何种应对的记述。

### 详细分析的方针

#### 重要度判定基准
对各错误依据以下基准赋予重要度（高/中/低）。

| 重要度 | 判定基准 | 判定示例 | 输出方针 |
|--------|---------|--------|----------|
| **高** | 对流程执行有直接不良影响、IM-BPM 导入失败的可能性高、业务流程本身无法成立 | 开始/结束事件缺失、无效的引用、死锁结构 | **单独立项** |
| **中** | 导入可成功但流程执行时会产生警告/错误、实现时需要额外作业 | 非标准记法、属性值的含糊性 | **单独立项** |
| **低** | 对规格化・实现・运用无直接影响，仅从提升未来可维护性的观点建议改善 | 工具误检测、未使用的资源定义、非正式的关联 | **仅计入汇总的件数。不单独立项** |


#### 根本原因分析的方针
对各错误从以下观点推测根本原因，并提出多个方案。

1. **设计阶段的错误**
   - 对 BPMN 规格理解不足
   - 对需求或业务流程理解有误
   - 工具操作失误

2. **编辑・反映阶段的错误**
   - 部分修正时遗漏更新引用
   - 复制/粘贴后遗漏指定引用目标
   - 合并/重构时遗漏要素对应

3. **工具生成规格的限制**
   - BPMN 编辑工具（iGrafx 等）输出规格的限制
   - 依赖版本的记法差异
   - 导出时的非标准输出

4. **解析器/验证工具的实现极限**
   - 未支持要素类型的识别
   - 引用检查范围的限制
   - 嵌套结构的处理遗漏

#### 影响分析的方针
对各错误从以下观点分析影响。

| 观点 | 分析要点 |
|------|------------|
| **流程执行** | 流程执行时是否发生错误/警告、是否死锁、是否影响执行结果 |
| **IM-BPM 导入** | 是否导入失败、是否仅为警告、是否可忽略并继续 |
| **规格化** | 是否影响规格书的创建、说明是否变得含糊、是否存在误解的可能性 |
| **实现** | 实现脚本时是否需要额外作业、测试时是否发生问题 |
| **运用** | 运用时的维护是否变得困难、是否需要用户应对 |

#### 详细分析的限制
- 详细分析仅用于将 validate-bpmn.js 的输出分类为「实际 BPMN 的问题」还是「因验证工具实现极限导致的误检测」，并补充重要度・原因候选・影响・应对方针。

## 验证结果的记载规则

### BPMN 记法错误
- **定义：** XML 语法缺陷、引用断裂、命名空间不一致、图形引用不一致等，可依据 BPMN 规格・引用完整性客观判定的内容。
- **VAL 系 ID 的赋予条件：** 仅赋予与 validate-bpmn.js 的 ERROR / WARN 一一对应的项，或对同一原因的同类日志汇总整理后的结果。
- **进一步细分：**
  - **实际 BPMN 的问题（需应对）**：对流程执行产生不良影响，或在 IM-BPM 导入时很可能产生错误的问题。
    - 例：开始/结束事件的缺失、必填属性的缺失、无效的引用、流程结构的矛盾
  - **因验证工具实现极限导致的误检测（可忽略）**：实际 BPMN XML 正确，但验证工具无法识别该要素的问题。
    - 例：对不在工具已知集合（known set）中的要素类型的引用检查失败、因解析器限制导致的误检测
- **响应方针：**
  - 实际 BPMN 的问题（重要度「高」或「中」）：明确可机械修正的范围，并具体记载修正步骤或修正候选。
  - 实际 BPMN 的问题（重要度「低」）：不单独立项，仅计入汇总的件数。
  - 验证工具误检测：不单独立项。仅计入汇总的「因工具实现极限导致的误检测」件数。
- **禁止事项：** 不得将 validate-bpmn.js 中不存在的自定义检查结果作为 VAL-ERR / VAL-WARN 立项。


## 向 to-be-discussed.md 记载的模板

### 错误 ID
 - 对 validate-bpmn.js 直接输出的 ERROR / WARN，赋予 VAL-ERR-＜连号＞ / VAL-WARN-＜连号＞。

### 「BPMN 语法・引用完整性验证」用的模板构成
```md
### <章节名>

#### <错误ID>. <种别>: <对象要素名>

- **对象要素**: <要素名>（<要素种类> / <泳道名> / <前后要素名等>）
- **重要度**: 高|中|低
- **问题内容**: <以通俗表达记载验证结果的错误种别>
- **原因候选**:
  1. 可能是<原因候选1>。
  2. 可能是<原因候选2>。
  3. 可能是<原因候选3>。
- **影响**: <按观点分别记载对规格化・实现・运用的影响>
- **应对方针**: <具体的修正步骤或改善方案>
```

#### 关于应对方针
- 「应对方针」最终应归结为以下之一：
  - ✅ **可立即修正**：明确记载修正步骤
  - ❓ **需要需求确认**：明确记载确认问题
  - ⏭️ **导入后应对**：明确记载导入时点的应对，并说明保留的理由

### 验证结果的输出目标
验证结果输出至 `to-be-discussed.md` 的「1. BPMN 语法・引用完整性验证结果」中，内容如下。

- **验证结果汇总**
  ```
  ### 验证结果汇总

  执行 `validate-bpmn.js` 的结果（退出码 X）。

  ERROR Y 件、WARN Z 件 → <PASS|FAIL>

  | 区分 | 件数 | 说明 |
  |------|------|------|
  | 实际 BPMN 的问题（需应对） | n 件 | 具体内容 |
  | 因工具实现极限导致的误检测 | m 件 | 具体内容 |
  ```

- **BPMN 记法错误**
  - 仅对重要度「高」或「中」的「实际 BPMN 的问题」单独立项
  - 重要度「低」的项目及「工具误检测」不单独立项（仅计入汇总件数）
  - 此处记载的 VAL 系项目仅限于 validate-bpmn.js 的直接输出

**向 `to-be-discussed.md` 反映的规则：**
- ERROR 行：必须反映至待讨论事项。但重要度「低」（含工具误检测）仅将件数记载于汇总中，不单独立项。
- WARN 行：仅将重要度「高」或「中」的反映至待讨论事项。重要度「低」不单独立项。
- 在保持输出的 [input] / [model] / [flow] / [io] 上下文信息的前提下进行整理。
