# JSSP Post-Generation Verification Skill

Responsible for quality verification and fixes of code generated by jssp-page-generator.
Execute the following steps **in order from top to bottom**, repeating fixes until the error count reaches 0.

---

## Step 1: JSSP Code Validation

```bash
node .claude/skills/jssp-page-generator/scripts/validate-jssp-code.js src/main/jssp/src/{feature-name}/
```

**Repeat fixes until there are 0 errors.**

Common detected patterns:
- `db.select()` / `db.execute()` parameters not wrapped with `DbParameter`
- Strings passed to `DbParameter.number()` (missing `Number()` conversion)
- Use of `var` (use `let` instead)
- `imds-selectbox` (non-existent class name; correct is `imds-select`)
- `imuiCalendar` altField referencing a hidden input
- imart tag `value` attribute enclosed in quotes
- Loading common modules with `include('**/common/**')` (correct is `load()`)
- `load('**/*.js')` calls with `.js` extension (extension is auto-added, resulting in `.js.js` and FileNotFoundException)
- Not receiving the return value of `Transaction.begin(...)`
- TIMESTAMP/DATE column bindings using datetime-like variable names such as `DbParameter.string(startAt|endAt|rangeFrom|rangeTo|...)` (causes type cast error in PostgreSQL)

> **If JSSP-JS-022 warning appears:** Open the corresponding SQL file and confirm whether the parameter is wrapped in `/*IF param != null*/.../*END*/`. If wrapped → false positive (note "SQL-side /*IF*/ guard confirmed" in summary). If not wrapped → fix to empty string fallback like `DbParameter.string(x || '')`.

## Step 2: DDL Type Validation (Only If DDL Was Generated)

Execute only if a DDL path was specified in the prompt. Skip if not specified.

```bash
node .claude/skills/jssp-page-generator/scripts/validate-ddl.js src/main/storage/system/products/import/basic/{feature-name}/{version}/
```

**Repeat fixes until there are 0 errors.**

Common detected patterns:
- PostgreSQL DDL using `NVARCHAR` / `VARCHAR2` / `NUMBER` / `DATETIME2` / `CLOB`
- Oracle DDL using `VARCHAR(` / `NVARCHAR2` / `DECIMAL` / `DATETIME2` / `TEXT` / `BOOLEAN`
- SQLServer DDL using `VARCHAR(` / `VARCHAR2` / `NUMBER` / `TIMESTAMP` / `CLOB` / `TEXT` / `BOOLEAN`
- `CREATE FUNCTION` / `CREATE TRIGGER` / `CREATE PROCEDURE` / `CREATE VIEW` in DDL (causes import failure)
- `CHECK` / `FOREIGN KEY` / `EXCLUDE` constraints defined in CREATE TABLE or ALTER TABLE
- ODBC escapes `{d '...'}` / `{t '...'}` / `{ts '...'}` / `{fn ...}` / `{oj ...}` / `{call ...}` in shared DML file (`*-dml.sql`)

---

## Step 3: tsc Type Check

```bash
bash .claude/skills/jssp-page-generator/scripts/check-types.sh src/main/jssp/src/{feature-name}/
```

**Repeat fixes until there are 0 issues.**

Common detected patterns:
- Type mismatch such as `result.data === 0` (updated count is `result.countRow`)
- Access to methods or properties not present in d.ts

---

## Step 4: Manual Check

Open `.claude/skills/jssp-page-generator/reference/post-generation-verification.md` with the Read tool and execute all steps.
