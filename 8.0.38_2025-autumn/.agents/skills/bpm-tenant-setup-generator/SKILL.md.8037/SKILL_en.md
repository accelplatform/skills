# Tenant Setup Material Generation Skill (for BPMN)

## Purpose

A skill for incorporating BPMN files into the tenant setup materials generated by jssp-tenant-setup-generator (.agents/skills/jssp-tenant-setup-generator/SKILL.md).
The generated materials can be loaded from Tenant Environment Management (Tenant Setup).

|---------|-------------|--------|

| BPMN import JS | `<key>/initialize/<version>/<key>_bpm_import.js` | - |
| Role/authorization materials (recovery only when not yet generated)|See `.agents/skills/jssp-tenant-setup-generator/SKILL.md`|-|

### Rules for Selecting the import-config

- If, while assembling the first setup materials of the same release, role/authorization materials, DDL, etc. have already been generated in an existing import-config, append the `<extends-import>` for the BPMN import to **that same config (normally config-1)**. You must not increment the config number merely because a config already exists.
- Create a new config-(N+1) only when the existing config has already been released and loaded into the tenant and can no longer be changed, when the user has explicitly stated a differential release / version upgrade, or when the execution order needs to be separated. If it is unclear whether this applies and the outcome would differ, confirm with the user.
- If the existing config has no `<extends-import>`, create one after `<database>` and `<tenant-master>`. If one already exists, add the `<extends-import-class>` following the execution order in [reference/bpm-import.md](reference/bpm-import.md).

- For `<version>`, if an existing version folder is present under `src/main/storage/system/products/import/basic/<key>/` (a folder that already contains role/authorization materials, DDL, BPMN, etc.), **use that folder name as-is**. You must not generate the BPMN-related materials (the import BPMN and `<key>_bpm_import.js`) into a separate new version folder on their own. Only when no existing folder is present (the first generation by this skill) should you newly determine it according to the resolution order in `.agents/skills/jssp-tenant-setup-generator/SKILL.md` (the `version` in spec.json → the `<version>` in module.xml/pom.xml → `1.0.0`).
  - A version upgrade (the practice of raising `spec.version` and creating a new version folder; pattern (I) in `.agents/skills/jssp-tenant-setup-generator/reference/multi-config.md`) is performed only when the user explicitly instructs a version upgrade. During this skill's generation process, the AI must not ask whether a version upgrade is needed, nor automatically switch to a new version folder on the grounds that the pom.xml version has changed.
- The value of `<key>` follows that used by `.agents/skills/jssp-tenant-setup-generator/SKILL.md`.
- `<file>` carries over the source file name as-is.

## When to Use

When the user makes requests such as:

- "I want to load the BPMN via tenant setup"
- "I want to load the BPMN together with the generated materials via tenant setup"

## Generation Procedure

### 1. Generate the Role/Authorization Materials and DDL (only when not yet generated, for recovery purposes)

Editing and deploying a BPM project requires permissions for the executing user (role/authorization materials), and if the DDL (table definitions) has not been applied to the target tenant, the subsequent import will fail. For both, see `.agents/skills/jssp-tenant-setup-generator/SKILL.md`.

- If both the role/authorization materials and the DDL have already been generated, skip this step and proceed to step 2.
- Only when some materials have not been generated, carry out—as recovery—just the parts of the generation procedure in `.agents/skills/jssp-tenant-setup-generator/SKILL.md` that generate the missing role/authorization materials and DDL. Do not regenerate other materials such as menus, the job scheduler, or portlet DML if they have already been generated.

### 2. Requirements Gathering (BPMN)
- Decide which BPMN files to load from tenant setup.
  - Display a list of *.bpmn files under `doc/<BPM process name>-prompt/` together with a selection field.
  - Copy the selected BPMN files to "Import BPMN (bpmn)" in "Output Locations".
- Gather the values required to load them into the BPM Process Designer (for details, see "Specification in spec.json" in [reference/bpm-import.md](reference/bpm-import.md)).
  - `projectId`: The Process Designer project ID. Present the artifactId as the initial value and confirm with the user.
  - `projectName`: The Process Designer project name. Present the `<name>` from pom.xml as the initial value and confirm with the user.
  - `files`: The list of selected/copied BPMN file names.

### 3. Generate the BPMN Setup Materials

Because the `.agents/skills/jssp-tenant-setup-generator/scripts/build-setup-import.js` build script does not support `bpmImport`, the following is generated/appended directly by this skill without running the build script.

- Generate `<key>_bpm_import.js`. Its processing content follows "Processing Content of the Extends Import JS" and "Details of Direct Java Calls" in [reference/bpm-import.md](reference/bpm-import.md) (`checkProjectExists` → `createProject` if it does not exist → `uploadOrUpdateBpmnFile` for each `files` entry; none of these use the REST API — all are direct Java calls via `ProjectFactory` / `ResourceFactory`). Use the `projectId` / `projectName` / `files` gathered in step 2.
- Manually add an `<extends-import-class>...<key>_bpm_import.js</extends-import-class>` line to the `<extends-import>` section of the `import-<artifactId>-config-<N>.xml` determined by "Rules for Selecting the import-config" above. If lines for `extendsImport` / `workflowImport` / `logicImport` have already been output, append after them (for the order, see "Execution Timing" in [reference/bpm-import.md](reference/bpm-import.md)).
